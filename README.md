# 微信消息提示 · WeChatToast

[![release](https://img.shields.io/github/v/release/PepsiColaya/desktop-toast)](https://github.com/PepsiColaya/desktop-toast/releases/latest)
[![license](https://img.shields.io/github/license/PepsiColaya/desktop-toast)](LICENSE)
[![platform](https://img.shields.io/badge/platform-Windows%2010%2F11-blue)](https://github.com/PepsiColaya/desktop-toast)

> 微信躲在后台时，也能一眼看到**谁发的、说了什么**。

> **第三方工具声明**：本项目为个人作品，与腾讯公司无关，未获其授权或认可。「微信」仅用于说明本工具适用的软件，不构成任何官方关联。程序只读取 Windows 通知中心，不修改、不注入微信客户端。图标为原创设计（靛蓝卡片造型），未使用微信官方标识。

![预览](docs/screenshot.png)

PC 微信最小化后，来消息只有任务栏闪一下，不看一眼根本不知道是谁找。这个小工具会在屏幕角落浮出一张卡片，直接告诉你会话名、发送者和消息内容，3 秒后自动淡出，不用再点开微信确认。

## 特性

- **悬浮卡片**：圆角 + 柔和阴影，显示「会话名 · 发送者」和消息正文（两行内，超出省略）
- **真实头像**：把头像图片按「会话名.png」放进 `avatars/` 目录即可自动显示，未匹配的用渐变首字兜底
- **自动消失**：默认 3 秒淡出，鼠标移上去暂停倒计时，移开继续
- **多条堆叠**：同时来多条会依次排列，超出同屏上限的自动排队
- **同会话合并**：同一会话连着来消息时原地更新那张卡片并显示条数（如「产品研发群 · 张伟（3）」），不会被同一个群刷屏
- **多应用监听**：不只是微信——设置里会列出当前正在运行的应用，勾谁就提醒谁，默认只勾微信
- **简略模式**：可以关掉正文，卡片只显示「谁找的你 + 有一条新消息」，旁边有人也不怕
- **点击跳转**：点卡片直接把微信唤到前台
- **多屏跟随**：默认在鼠标所在的那块屏幕弹出，也可以固定到主屏
- **免打扰名单**：不想被某几个群打扰时，在设置里把它们加进去即可，改完即时生效
- **开机自启**：设置里勾一下即可，写当前用户的启动项，不需要管理员权限
- **可视化调参**：内置设置面板，左侧拖滑块，右侧实时预览，所见即所得
- **配置永久保存**：改完自动落盘到 `%APPDATA%\WeChatToast\config.json`，重启、换 exe 位置都不会丢
- **深色 / 浅色主题**，宽度、缩放、圆角、阴影、透明度、位置、时长全部可调
- **托盘常驻**：支持暂停监听、单实例保护
- **日志可查**：运行日志写在配置目录下，托盘菜单「查看日志」一键打开，出问题能直接定位

## 原理

先说结论：**这个工具不读微信的界面，也不碰它的数据库，而是读 Windows 通知中心。**

但这里有个前提必须先说清楚，否则你会以为程序坏了：

> **微信 4.x 并不往 Windows 通知中心推送消息。** 本工具对微信无效。
> 详见下面的「[微信 4.x 为什么收不到](#微信-4x-为什么收不到)」。

对**会**推送系统通知的应用（企业微信、QQ NT、钉钉、飞书、Outlook、Slack、Telegram、
以及各种走 Windows 通知中心的桌面程序），本工具工作正常，文本结构也很规整：

| 行 | 含义 | 示例 |
|---|---|---|
| `text[0]` | 应用名 / 标题 | `企业微信` |
| `text[1]` | 会话名 | `产品研发群` |
| `text[2]` | 发送者 + 正文 | `张伟 : 这个版本的接口文档我下午更新一下` |

好处是：**不注入目标进程、不读数据库、不碰内存**，应用小版本升级也不容易失效。

### 怎么判断通知是哪个应用发的

不能靠第一行猜——不同应用的第一行含义不一样（微信是应用名，Microsoft Store 是通知标题）。
所以读通知自带的 `app_info`：

| 字段 | 示例 | 用途 |
|---|---|---|
| `app_user_model_id` | `WorkBuddy.WorkBuddyAI` | 应用的唯一标识，最可靠 |
| `display_info.display_name` | `WorkBuddy AI` | 给人看的名字 |

设置面板里勾选的每个应用，会存下一组小写匹配串（显示名 + exe 名），
收到通知时拿 AUMID 和显示名去匹配，命中才弹卡片。

**关键点：只匹配应用标识，不匹配消息正文。** 否则一条正文里出现「微信」两个字的消息就会被误判成微信消息。

代价是：有些应用拿不到 `app_info`（老式 Win32 程序、部分 UWP），
这种情况会退回「第一行是不是微信」的旧规则，只有微信能被识别出来。

### 微信 4.x 为什么收不到

不是配置问题，也不是权限问题，是**微信本身不提供这个能力**。四条可能的入口逐条实测结果：

| 入口 | 实测结果 | 结论 |
|---|---|---|
| Windows 通知中心（Toast） | 系统通知库 `wpndatabase.db` 里共 165 个应用处理器，**微信相关 0 个** | 微信从未注册过通知处理器，一条 Toast 都没推过 |
| UI Automation（读控件树） | 根窗口 → 1 个 `MMUIRenderSubWindowHW` 面板 → **0 个子控件** | 界面上根本没有「控件」这个概念 |
| 截屏主窗口 + 检测未读红点 | 窗口可见时能抓到（含 1779 个红色像素）；**最小化/隐藏后抓出来全是黑的** | 只在微信开着且在前台时有效，等于没用 |
| 自绘弹窗（盯窗口 + OCR） | 微信预建了 2 个 176×199 隐藏窗口（位置 872,409），疑似弹窗本体 | 待实测 |

**为什么 UIA 读不到**：微信 4.x 的界面是自绘引擎渲染的——所有内容画在同一块
`MMUIRenderSubWindowHW` 画布上（880×640 的单个 HWND）。
界面上不存在「按钮」「列表项」这种控件对象，所以无障碍接口**无从暴露**，
不是腾讯把接口关掉了、也不是我们没找对姿势。
主程序 `Weixin.dll` 里也确实搜不到 `UiaRootObjectId` / `qwindowsuiautomation` / `QT_ACCESSIBILITY`。

**为什么截图也不行**：实测三种窗口状态下的抓图结果——

| 窗口状态 | 抓图尺寸 | 结果 |
|---|---|---|
| 可见 | 896×648 | 正常，含未读红点 |
| 最小化到任务栏 | 160×28 | 全黑 |
| 关到托盘（隐藏） | 160×28 | 全黑 |

而「需要提醒」的场景恰恰是微信不在前台的时候。所以截主窗口这条路走不通。

微信的设置里也没有「使用系统通知」这类开关（4.1.15.13 的「通知」页只有两个声音开关）。

**那还能怎么办？**

1. **盯微信的自绘弹窗** —— 微信在后台收到消息时会自己弹一个窗口（那两个 176×199 的隐藏窗口
   很可能就是它）。可以监听「微信进程显示了一个小窗口」这个事件，再把窗口截图 OCR 出文字。
   硬伤：微信不弹窗（关了通知、或主窗口在前台）时就什么都拿不到；
   OCR 对彩色群名、表情符号的准确率只有七八成。
   `tools/diagnose.py --watch` 就是用来验证这条路的。
2. **换一个会推送系统通知的 IM** —— 企业微信、QQ NT、钉钉、飞书在 Windows 上都走通知中心，
   本工具开箱可用，这是最省事的路。
3. **手机通知转发到电脑** —— 手机装通知转发类工具，把微信通知 POST 到电脑上的小服务，
   电脑端直接复用本项目的卡片。完全不碰微信客户端，内容还是原文，准确率 100%。
4. **解密微信本地消息库** —— 技术上可行（`db_storage\message\*.db` 是 SQLCipher 加密，
   密钥在进程内存里），但要读别的进程内存，会被杀软和微信风控盯上，升级即失效。
   **本项目不提供这个能力。**

## 环境要求

- Windows 10 1809+ 或 Windows 11
- 目标应用会往 Windows 通知中心推消息（企业微信 / QQ NT / 钉钉 / 飞书 / Outlook 等；
  **微信 4.x 不属于这一类**，见上）
- Python 3.10+（仅源码运行需要）

## 使用

### 方式一：直接跑 exe

从 [Releases](https://github.com/PepsiColaya/desktop-toast/releases/latest) 下载 `WeChatToast.exe` 双击运行。托盘出现靛蓝色的卡片图标就是启动成功了，**没有主窗口是正常的**。

首次启动单文件 exe 需要解压，会等 3～8 秒。

### 方式二：源码运行

```bash
git clone https://github.com/PepsiColaya/desktop-toast.git
cd desktop-toast
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
python main.py
```

或者双击 `run.bat`（用的是系统 Python，需要先 `pip install -r requirements.txt`）。

> **装不上依赖时**：如果报 `Could not find a version that satisfies the requirement PySide6-Essentials`，
> 说明当前 pip 镜像源缺包，加 `-i https://pypi.org/simple` 换成官方源再装即可：
> `pip install -i https://pypi.org/simple -r requirements.txt`

> 想跑 `tools/` 下的诊断脚本，再装开发依赖：`pip install -r requirements-dev.txt`
> （多了 uiautomation、Pillow 和 OCR 相关的 winrt 包，打 exe 用不到）

### 打开设置

右键托盘图标 → **设置…**（双击托盘图标也可以）。

**改完不用点保存**——停手半秒后自动写入配置并即时生效，面板底部会闪一下「已自动保存」。直接关窗口也不会丢，关闭前会再存一次。

面板里能改的：

| 分组 | 内容 |
|---|---|
| 外观 | 主题、卡片宽度、整体缩放、圆角、阴影扩散、不透明度、卡片间距 |
| 监听应用 | 当前正在运行的应用列表，勾选哪些就提醒哪些（默认只勾微信） |
| 位置 | 显示位置（四角）、显示屏幕（跟随鼠标 / 主屏）、距屏幕边缘 |
| 行为 | 停留时长、同屏最多几张、悬停暂停、点击打开微信、同会话合并、卡片显示正文、开机自启 |
| 免打扰 | 输入会话名回车即可加入，该会话来消息不再弹卡片 |
| 头像 | 头像目录位置，一键打开 |

「在桌面试一下」会用当前参数弹一条真实卡片，方便确认实际效果。

监听应用、免打扰、开机自启、显示屏幕、显示正文这几项改完都是**即时生效**，不需要重启程序。

## 配置项

配置自动保存在：

| 运行方式 | 位置 |
|---|---|
| exe | `%APPDATA%\WeChatToast\config.json` |
| 源码 | 项目根目录 `config.json` |

放在 `%APPDATA%` 的好处是：exe 被移动、复制、重新下载覆盖，配置都还在。旧版本留在 exe 同目录的 `config.json` 会在首次启动时自动迁移过来。

设置面板覆盖了常用项，其余可直接改 `config.json`（改完重启程序生效）：

| 键 | 默认值 | 说明 |
|---|---|---|
| `theme` | `dark` | 主题，`dark` / `light` |
| `card_width` | `340` | 卡片宽度（px），240–560 |
| `scale` | `1.0` | 字号与内边距整体缩放，0.8–1.5 |
| `radius` | `14` | 圆角（px），0–24 |
| `shadow` | `16` | 阴影扩散范围（px），0–30 |
| `opacity` | `0.96` | 背景不透明度，0.4–1.0（文字始终不透明） |
| `gap` | `8` | 卡片间距（px），0–24 |
| `position` | `top-right` | 位置：`top-right` / `top-left` / `bottom-right` / `bottom-left` |
| `screen` | `cursor` | 显示在哪块屏幕：`cursor` 跟随鼠标 / `primary` 主屏 |
| `margin` | `22` | 距屏幕边缘（px） |
| `duration_ms` | `3000` | 停留时长（毫秒） |
| `max_visible` | `3` | 同屏最多几张 |
| `fade_in_ms` / `fade_out_ms` | `170` / `280` | 淡入淡出时长 |
| `hover_pause` | `true` | 鼠标悬停时暂停倒计时 |
| `click_to_open_wechat` | `true` | 点击卡片唤起微信 |
| `merge_same_source` | `true` | 同一会话连续消息合并成一张卡片并显示条数 |
| `show_content` | `true` | 卡片是否显示消息正文；`false` 时只显示「有一条新消息」 |
| `poll_interval_ms` | `1000` | 通知轮询间隔 |
| `ignore_sources` | `[]` | 不提醒的会话名，如 `["某工作群"]` |
| `enabled_apps` | 微信 | 只提醒这些应用的通知，见下方说明 |
| `autostart` | `false` | 开机自启（对应 HKCU 启动项） |
| `avatar_dir` | 配置目录下 `avatars` | 头像图片目录 |

`enabled_apps` 的结构如下。`match` 是一组小写子串，收到通知时拿 AUMID 和显示名去包含匹配；
空数组表示**什么都不弹**：

```json
"enabled_apps": [
  {"key": "wechat", "name": "微信", "match": ["微信", "wechat", "weixin"]},
  {"key": "chrome.exe", "name": "Google Chrome", "match": ["google chrome", "chrome.exe", "chrome"]}
]
```

数值超出范围会自动夹紧到合法区间。

## 头像

微信 4.x 的通知里**不带头像**，本地头像缓存又是哈希命名、无法对应到会话名，所以程序不会自动抓取头像。

替代方案是「按名字匹配」：把头像图片命名成会话名，放进头像目录即可（默认 `%APPDATA%\WeChatToast\avatars`，设置面板里点「打开目录」可直接跳过去）。

```
avatars/
├── 产品研发群.png
├── 李静.jpg
└── 家里群.webp
```

- 支持 `png / jpg / jpeg / webp / bmp`
- 会话名要和微信里显示的**完全一致**（群名或备注名）
- 文件名里的 `\ / : * ? " < > |` 会被替换成 `_`
- 没匹配到的会话自动用渐变首字占位，不影响使用

设置面板里点「打开目录」可以直接跳过去。头像按修改时间缓存，换图后重启程序即可生效。

## 打包

```bash
build.bat
```

脚本会自动装依赖再调 PyInstaller，产物在 `dist/WeChatToast.exe`，约 40 MB（PySide6 占大头）。
打包只用 `requirements.txt`，`requirements-dev.txt` 里的诊断依赖不会进 exe。

用户端的配置和日志都在 `%APPDATA%\WeChatToast\` 下，exe 可以随便移动、复制、重新下载。

## 已知限制

- **微信 4.x 收不到**（[原因](#微信-4x-为什么收不到)）。这是微信本身不推系统通知导致的，与本程序无关
- **只读通知**，拿不到历史消息，也不能在卡片里直接回复
- 点击只能把目标应用唤到主窗口，**无法定位到具体某个会话**（微信 4.x 自绘，外部点不进去）
- 图片 / 表情 / 语音消息在通知里没有正文，卡片会显示「（新消息）」
- 应用本身会合并同一会话的连续消息，此时可能只弹一次
- 你正开着那个应用、且正看着那个会话时，它不发通知，所以不会弹卡片——这是符合预期的
- **只支持走 Windows 通知中心的应用**。有些程序自己有独立的消息窗口（比如部分游戏客户端、
  自绘 UI 的工具），根本不往系统通知中心推消息，勾了也收不到
- 个别应用拿不到 `app_info`，无法识别应用标识，只有微信能用「首行是微信」的兜底规则识别出来
- 监听应用列表来自「有可见窗口的进程」，纯后台运行的应用不会出现在列表里；
  重新打开它的窗口后点「刷新」即可

## 技术备注

`tools/` 下是开发时用来确认可行性的脚本：

| 脚本 | 用途 |
|---|---|
| `diagnose.py` | 一次性体检：通知权限、通知中心现状、微信窗口、历史推送记录、UIA 树，并给出小结 |
| `diagnose.py --watch 60` | 盯 60 秒，实时打印新系统通知 / 微信新建的窗口，并自动截图 OCR |
| `grab_window.py` | 把微信的任意窗口（含隐藏窗口）抓成 PNG，用来判断它是什么 |
| `probe_windows.py` | 枚举微信顶层窗口，看窗口类和标题 |
| `dump_uia.py` | 导出微信主窗口的 UIA 控件树（结论：空的） |
| `test_notify.py` | 验证通知访问权限与 Toast 的文本结构 |

排查「收不到消息」时，先跑 `diagnose.py`：

```bash
.venv\Scripts\python.exe tools\diagnose.py
```

它会直接告诉你三条入口哪条通、哪条不通。

如果你要适配其他微信版本，也建议先跑这个脚本确认可读性。

回归测试（不需要微信、不弹窗，纯逻辑校验）：

```bash
python tools/smoke_test.py
```

覆盖消息解析（含正文里带中文冒号的误判）、折行（英文不拆词）、配置规范化、同会话合并计数。
