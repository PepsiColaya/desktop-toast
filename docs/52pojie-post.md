## 正文

【起因】

工作机上的 IM 常年最小化，来消息只有任务栏闪一下。想看一眼是谁找，就得把窗口整个拉起来，看完再最小化——一天几十次，纯属折磨。

也试过几个现成方案，都不太合适：有的要装客户端全家桶，有的直接读本地数据库（SQLCipher 加密，还得跟着版本改），还有的要注入进程，杀软第一个不答应。

后来想到 Windows 自己就有现成的通道：**通知中心**。应用把通知交给系统，系统负责弹 Toast——那我就别费劲去啃某个具体应用了，直接读系统通知就行。于是有了这个小工具。

【效果】

应用缩在后台时，屏幕角落浮出一张卡片，告诉你哪个会话、谁发的、说了什么，3 秒自动淡出。鼠标移上去会暂停倒计时，点一下把应用唤到前台。

【图1：卡片实际效果】

同时来好几条会依次往下排，超出同屏上限的自动排队，不会糊成一坨。同一个会话连着来消息时，卡片会原地更新并显示条数（如「示例群 · 张三（3）」），不会被同一个群刷屏。

【功能一览】

· 悬浮卡片：圆角 + 柔和阴影，两行正文，超长省略
· 真实头像：把图片按「会话名.png」丢进头像目录就能显示，没匹配上的用渐变首字兜底
· 自动消失：默认 3 秒，悬停暂停，移开继续
· 多条堆叠：同屏最多几张可调，多出来的排队
· 同会话合并：连续消息原地更新，不刷屏
· 多应用监听：设置里列出系统通知里出现过的应用，勾谁提醒谁，默认只勾「手机连接」
· 手机 App 细分：展开「手机连接」还能只勾想收的手机 App（微信、QQ、电话…），勾哪个收哪个
· 简略模式：关掉正文，只显示「谁找的你 + 有一条新消息」，旁边有人也不怕
· 点击跳转：点卡片按消息来源唤应用——电脑上的拉窗口到前台，手机转发来的就打开「手机连接」
· 多屏跟随：默认在鼠标所在那块屏弹出，也可以固定到主屏
· 免打扰名单：不想被某几个群打扰，加进去即可，改完即时生效
· 开机自启：写当前用户的启动项，不需要管理员权限
· 可视化调参：宽度、缩放、圆角、阴影、透明度、间距、位置、时长全可调
· 深浅两套主题
· 配置永久保存：改完自动落盘，不用点保存，重启不丢
· 托盘常驻：可暂停监听，单实例保护

【先说清楚：微信 4.x 用不了】

这条得放前面，不然你下载完会觉得是程序坏了。

**微信 4.x 根本不往 Windows 通知中心推消息**，所以本工具对微信无效。这不是配置问题、也不是权限问题，是微信本身没提供这个能力。四条可能的入口我逐条实测过：

· **通知中心（Toast）** —— 系统通知库 `wpndatabase.db` 里共 165 个应用处理器，微信相关 **0 个**。它从注册到现在一条 Toast 都没推过。
· **UI Automation（读控件树）** —— 根窗口 → 1 个 `MMUIRenderSubWindowHW` 面板 → **0 个子控件**。界面上根本没有「控件」这个概念。
· **截主窗口 + 找未读红点** —— 窗口可见时能抓到（含 1779 个红色像素）；最小化/隐藏后抓出来 **160×28 全黑**。而「需要提醒」的场景恰恰是它不在前台的时候，等于没用。
· **微信设置里找开关** —— 4.1.15.13 的「通知」页只有两个声音开关 + 发现页管理 + 朋友圈提醒，**从来没有「在通知中心显示」这种开关**。

**为什么 UIA 读不到**：微信 4.x 换成了 Qt 自绘引擎，所有内容画在同一块 `MMUIRenderSubWindowHW` 画布上（880×640 的单个 HWND）。界面上不存在「按钮」「列表项」这类控件对象，无障碍接口**无从暴露**——不是腾讯把接口关掉了，也不是我们没找对姿势。主程序 `Weixin.dll` 里也确实搜不到 `UiaRootObjectId` / `qwindowsuiautomation` / `QT_ACCESSIBILITY`。

顺带一句：网上说的「微信 3.9.x 能用」是真的，3.9 是 Duilib 真控件树，UIA 读得到。但 3.9 有强制升级和安全风险，不建议为了这个功能回退。

**那这个工具给谁用？** 给所有走系统通知中心的应用：企业微信、QQ NT、钉钉、飞书、Outlook、Slack、Telegram、WorkBuddy，以及各种走通知中心的桌面程序。这些开箱可用。

【怎么实现的】

这部分是重点，也是踩坑最多的地方。

一、先试的正路，走不通

最直觉的做法是 UI Automation：遍历目标窗口的控件树，把会话列表和消息文本读出来。这个思路在旧版 IM 上是常见做法，但新版本换自绘引擎之后彻底行不通——整块区域对 UIA 来说就是一张空白画布。这条路直接判死。

二、换个思路：读通知中心

会推送系统通知的应用，消息内容就在通知里。用 `UserNotificationListener` 就能把这些通知读出来，不需要任何特殊权限之外的骚操作。

读出来的文本结构非常规整，通常三行：

　　text[0]　应用名　　企业微信
　　text[1]　会话名　　示例群
　　text[2]　发送者+正文　　张三 : 这个版本的接口文档我下午更新一下

`text[2]` 是「发送者 + 正文」拼在一起的，得切开来。

这里不能简单地按第一个冒号切——正文本身完全可能带冒号（比如「时间：明天下午三点」），一刀下去就把正文切坏了。实际用的是一条带约束的正则：从行首开始匹配，发送者最长 20 个字符，后面紧跟中英文冒号再跟空白。

　　　　^(.{1,20}?)\s*[:：]\s+(.+)$

限定长度是为了兜底：真人昵称很少超过 20 个字，超过的基本就是正文里的冒号，不匹配就整段当正文，至少不会切错。另外还会排除掉候选发送者里带句读标点的（「，。！？；」这些），群聊和单聊都走这一套。

三、怎么判断通知是哪个应用发的

不能靠第一行猜——不同应用第一行含义不一样（有的是应用名，有的是通知标题）。所以读通知自带的 `app_info`：

· `app_user_model_id`　应用的唯一标识（如 `WorkBuddy.WorkBuddyAI`），最可靠
· `display_info.display_name`　给人看的名字

设置面板里勾选的每个应用，会存下一组小写匹配串（显示名 + exe 名），收到通知时拿 AUMID 和显示名去匹配，命中才弹卡片。

**关键点：只匹配应用标识，不匹配消息正文。** 否则一条正文里出现「微信」两个字的消息就会被误判。

四、几个必须处理的细节

· 首次启动要建基线。通知中心里存着历史通知，不做处理的话程序一启动就会把几十条旧消息全弹一遍。做法是首次运行时把现有通知的「ID → 文本签名」全部记下来，只记录不弹窗。
· 判断「新」不能只看 ID。同一条通知可能因为内容更新（比如连发两条被合并）而文本变化，所以比对的是 ID 对应的文本签名，签名变了才算新消息。
· 去重。用「会话 + 发送者 + 正文」做 key，4 秒窗口内重复的直接丢弃。
· 用轮询而不是事件。`UserNotificationListener` 其实提供了 `NotificationChanged` 事件，但在 PyWinRT 里维持回调对象的生命周期比较别扭，回调还落在别的线程上，得自己再往 UI 线程转一道。相比之下 1 秒一次的 `get_notifications_async` 简单、稳、开销可以忽略，就选了轮询。
· 热更新。改免打扰名单、改轮询间隔不用重启，设置面板改完直接生效。

五、UI 部分

PySide6 画的。卡片是 QPainter 自绘：先叠几层递减透明度的圆角矩形做阴影，再画主体。背景单独设透明度，文字保持不透明——不然整张卡片一起半透明，字会糊。

堆叠用 QPropertyAnimation 做位移和淡入淡出，新卡片插进来时其余卡片平滑下移。

折行也踩了坑：按字符数硬切会把英文单词从中间截断，改成按 token 切之后正常了。

【安全性说明】

这类工具大家最关心的应该是这个，我一次说清楚：

· 不联网。程序没有任何网络请求，不收集、不上传任何数据。
· 不注入进程。没有 DLL 注入，没有 Hook，不碰目标应用的内存。
· 不读数据库。目标应用的本地库（SQLCipher 加密的那些）程序压根没去动。
· 只读系统通知。走的是 Windows 官方 `UserNotificationListener` API，和系统通知中心看到的是同一份数据。
· 源码全公开，MIT 协议，不放心的可以自己审、自己编。

关于杀软误报：PyInstaller 单文件打包出来的 exe 有一定概率被某些杀软标记，这是打包方式的通病，不是程序行为异常。介意的话直接用源码跑，依赖就几个包，`pip install -r requirements.txt` 然后 `python main.py` 就行。

【使用方法】

1. 下载 `DesktopToast.exe`，双击运行。托盘出现**靛蓝色卡片**图标就是启动成功了，没有主窗口是正常的。
2. 右键托盘图标 → 设置…，在「监听应用」里勾上你要提醒的程序（默认勾了「手机连接」）。改完直接关窗口，自动保存。
3. 想暂停就点托盘菜单的「暂停监听」。

一个前提开关必须打开，否则读不到任何东西：

· Windows → 设置 → 隐私和安全性 → 通知 → 允许应用访问你的通知

配置文件在 `%APPDATA%\DesktopToast\config.json`，想手动改的可以直接编辑。exe 挪位置、重新下载覆盖，配置都不会丢。

顺带说下改名：这工具原名 `WeChatToast`，为了不再把适用范围限定在微信上，现已统一改为 `DesktopToast`。老用户升级时旧配置目录会自动搬过来，不用重设。

【已知限制】

提前说清楚，免得下载完发现不符合预期：

· **微信 4.x 收不到**，原因见上文。这是微信的限制，不是本工具能绕过去的。
· 只读通知，拿不到历史消息，也不能在卡片里直接回复。
· 点击只能把应用唤到主窗口，没法定位到具体某个会话。
· 图片、表情、语音消息在通知里没有正文，卡片会显示「（新消息）」。
· 应用本身会合并同一会话的连续消息，这时候可能只弹一次。
· 你正开着目标应用、且正看着那个会话时，它不发通知，所以不会弹卡片。这是符合预期的。
· 目标应用如果关了系统通知权限，本工具收不到任何东西。
· 拿不到 `app_info` 的老式 Win32 程序会退回「第一行是不是微信」的旧规则，识别能力有限。
